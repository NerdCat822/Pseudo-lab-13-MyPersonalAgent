# 에이닷 노트 기능 반영 (v0.3)

작성일: 2026-10-25 · 상태: 구현·검증 완료(에뮬레이터 + 실제 OpenAI API), 실기기 미검증

SK텔레콤 에이닷 노트의 기능 구성(2026년 기준 기사·뉴스룸)을 기준으로, 개인용 회의 녹음 앱에 맞게 옮긴 내용이다.

## 1. 기능 대응표

| 에이닷 노트 | 이 앱 | 비고 |
|---|---|---|
| 실시간 받아쓰기 | 녹음 화면에 자막이 바로 쌓임 (`gpt-live-transcribe`) | 녹음마다 켜고 끔. 화자 구분 없음, 녹음 종료 후 화자별 받아쓰기로 대체 |
| 실시간 요약 (일정 시간마다) | 기본 2분·300자마다 구간 요약 1~3줄, 노트에 시간대별로 남음 | `LIVE_SUMMARY_MIN_SEC`, `LIVE_SUMMARY_MIN_CHARS` |
| 템플릿: 요점 정리 / 회의록 / 강의 노트 | 회의록·요점 정리·강의 노트·생각 노트 4종 | 녹음 전·파일 가져올 때 선택, 저장 후 바꾸면 요약만 다시 만듦(전사 재사용) |
| AI 웹검색 | 노트 화면·녹음 화면의 **AI 질문**, ‘웹’ 켜면 웹 검색 + 출처 링크 | 답의 `[mm:ss]`를 누르면 그 부분 재생 |
| 파일 업로드 (m4a·mp3·flac·wav) | **새 노트 → 파일 가져오기** (m4a, mp3, wav, flac, aac, ogg, opus 등) | 서버가 10분 단위로 나눠 받아쓰고 화자를 이어 붙임 |
| 편집 (실시간 요약·STT·템플릿) | 길게 눌러 수정: 요약 항목, 받아쓰기 문장, 실시간 요약, 제목, 화자 이름 | `PUT /summary`, `PATCH /utterances/{id}`, `PATCH /live-summaries/{id}` |
| 폴더 관리 | 노트 메뉴 → 폴더로 이동, 홈 상단 폴더 버튼으로 필터 | |
| 선택 공유, PDF·녹음 파일 저장 | 공유 시트에서 노트/실시간 요약/받아쓰기 선택 → 텍스트, PDF, 복사, 녹음 MP3 | PDF 한글 폰트는 첫 사용 때 Google Fonts에서 받음 |
| 링크 공유(비밀번호) | 미구현 | 서버가 Tailscale 사설망이라 외부 링크가 열리지 않음. 필요하면 Tailscale Funnel 등 공개 경로가 먼저 필요 |
| 다이어그램 | 미구현 | |

에이닷 노트에는 없지만 같이 넣은 것: 반복 키워드 집계(‘자주 나온 단어’), 녹음 중 중요 표시(별표), 노트 삭제, AI 질문 기록 보관.

## 2. 설계 결정

### 2.1 실시간 받아쓰기는 서버가 중계한다

기획서 v0.2는 "서버가 임시 키를 발급하고 앱이 OpenAI WebSocket에 직접 붙는" 구조였다. 구현하면서 서버 중계로 바꿨다.

- `gpt-live-transcribe`는 서버 VAD가 없다. 말이 끝날 때마다 클라이언트가 `input_audio_buffer.commit`을 보내야 한다(공식 가이드). 발화 끝 감지를 서버 한 곳(Python)에 두면 앱 두 플랫폼에 같은 로직을 둘 필요가 없고 테스트하기 쉽다.
- 서버가 자막을 바로 저장하므로, 녹음 중 AI 질문과 실시간 요약이 서버에서 자막을 읽을 수 있다.
- OpenAI 키는 임시 키조차 폰으로 가지 않는다(기획서 5.3 원칙 유지).

흐름: 앱 → `WS /meetings/{id}/live` (24 kHz PCM16 바이너리) → 서버 발화 감지(소음 수준 적응형 문턱값, 0.8초 무음 또는 15초마다 끊기, 말이 없는 구간은 보내지 않음) → OpenAI Realtime → 자막 JSON을 앱으로. 끊기면 앱이 현재 녹음 시각으로 다시 붙는다.

### 2.2 실시간 모드는 마이크를 한 번만 연다

실시간을 켜면 PCM 스트림 하나로 (1) 정확히 같은 길이의 WAV 세그먼트를 이어서 저장하고 (2) 같은 바이트를 서버로 보낸다. 녹음기 두 개를 동시에 여는 방식은 아이폰에서 검증할 수 없어 피했다. 부수 효과로 세그먼트 경계에서 녹음기를 껐다 켜던 공백(기획서 리스크 2)이 실시간 모드에서는 없다. 대가는 업로드 용량이다(WAV 384 kbps, AAC 48 kbps의 8배). 실시간을 끄면 기존 AAC 녹음을 그대로 쓴다.

### 2.3 화자 일관성: 자동 참조 음성 (기획서 5.2 구현)

첫 구간에서 화자별로 가장 긴 발화(2~10초)를 잘라 참조 음성으로 저장하고, 다음 구간부터 `known_speaker_names`(“참석자 1”, “참석자 2”)와 함께 보낸다. 2026-10-25 TTS 2인 대화로 확인: 25초 지점에서 나뉜 두 구간에서 두 사람이 끝까지 같은 이름으로 이어졌다. 최대 4명(OpenAI 한도), 2초보다 짧게만 말한 사람은 참조를 만들지 못해 구간마다 새 이름이 생길 수 있다.

## 3. 검증 기록 (2026-10-25)

검증 음성: OpenAI TTS로 만든 58초 한국어 2인 회의(남·여 목소리, 9개 발화, 결정사항·할 일·전문 용어 포함).

| 항목 | 결과 | 비용 |
|---|---|---|
| 2구간 업로드 → 화자 분리 + 회의록 | 화자 2명 일관, 제목 자동, 결정 4·할 일 3(담당·기한 포함) | $0.011 |
| 템플릿 전환(요점 정리) | 주제 8개 + 핵심 용어 6개, 재전사 없음 | +$0.005 |
| AI 질문 | 인용 [mm:ss]가 맞는 발화로 연결 | ~$0.002/회 |
| AI 질문 + 웹 | sqlite.org 출처 링크 | ~$0.012/회 |
| 실시간 받아쓰기(서버 경유) | 자막 6줄, 대본 시각과 일치, 20초 구간 요약 3개 | $0.019/58초 |
| 녹음 중 AI 질문 | 실시간 자막을 근거로 답, 인용도 자막으로 연결 | |

에뮬레이터(Android 16)에서 앱으로 직접 확인한 것: 녹음 화면 실시간 자막(부분 → 확정)과 30초 구간 실시간 요약, 녹음 종료 후 WAV 업로드 → 화자 2명 분리 → 회의록, 파일 가져오기(요점 정리), 템플릿 바꾸기, AI 질문 답과 `[mm:ss]` 눌러 재생, PDF 공유(Noto Sans KR 내장 2쪽), 녹음 중 AI 질문 시트. 에뮬레이터 마이크 경로를 거친 실시간 자막은 직접 스트리밍보다 오인식이 많다("SQLite" → "에스튜라이트"). 최종 받아쓰기는 녹음 파일로 다시 만든다.

검증 중 고친 버그: 녹음이 시작되면 레벨 막대가 고정 길이 리스트를 수정하다 화면 전체가 깨짐, 파일 선택기에서 m4a(음성 메모)가 비활성으로 보임(확장자 → MIME 변환이 `audio/mpeg`로 잡힘, `audio/*`로 변경), 답의 `[00:00]` 인용이 같은 초의 다른 발화로 연결됨.

백엔드 테스트 105개(가짜 OpenAI), 앱 테스트 10개(WAV 헤더·회전, 내보내기, 모델). 실기기(아이폰) 미검증: 실시간 모드의 화면 잠금 녹음, PDF 공유 시트, 파일 선택기.
